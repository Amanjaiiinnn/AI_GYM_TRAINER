# AI Real-Time Gym Trainer

A Streamlit web app that watches you exercise through your webcam, counts your reps, checks your form on five exercises, and speaks short coaching cues generated by Llama 3.3 (via Groq) out loud.

**Live demo:** [gymaitrainer.streamlit.app](https://gymaitrainer.streamlit.app/)

## Features

- **Live webcam analysis in the browser** over WebRTC, with a mirrored preview and a skeleton overlay drawn on every frame.
- **Five exercises:** Squats, Push-ups, Biceps Curls (Dumbbell), Shoulder Press and Lunges.
- **Automatic rep counting** using a two-stage (down → up) state machine per exercise.
- **Live form metrics** in the sidebar: joint angles plus status labels such as `GOOD DEPTH`, `SAGGING` or `SWINGING`.
- **Workout plans:** choose an exercise, number of sets and reps per set, and track total reps, reps in the current set and sets completed while you train.
- **AI voice coach:** Llama 3.3 70B on Groq writes a short cue for each workout event (start, set completed, workout completed, no pose, form problem) and gTTS speaks it in the browser.
- **Simple login and history:** sign in with a unique name; completed sets are saved to SQLite and today's totals are shown per exercise.

## How It Works

### 1. Login

`services/auth/login_wall.py` asks for a unique name. `get_or_create_user()` looks the name up in SQLite and creates the user if it doesn't exist. The user's id and name are kept in `st.session_state` for the rest of the session.

### 2. Workout plan

The sidebar collects the exercise, target sets and reps per set. **Start Workout** stores the plan, resets the counters and triggers the `workout_started` coaching event.

### 3. Video pipeline

When the workout starts, `streamlit-webrtc` opens the webcam in `SENDRECV` mode (Google's public STUN server is used for the peer connection). Every frame is handed to `VideoProcessorClass.recv()` in `services/vision/exercise_video.py`, which runs on the WebRTC worker thread:

1. Flip the frame horizontally so the preview behaves like a mirror.
2. Run the **MediaPipe Pose Landmarker** (`ml_models/pose_landmarker_full.task`) in `VIDEO` mode, with detection, presence and tracking confidence all set to 0.7. It returns 33 body landmarks.
3. Draw the skeleton, using only landmarks with visibility above 0.7.
4. Pass the landmarks to the detector for the selected exercise, which returns reps and form metrics.
5. Write a one-line status (for example `DEPTH: GOOD DEPTH`) at the bottom of the frame.
6. Store the latest metrics behind a `threading.Lock`, so the Streamlit script can read them safely.

If no person is found, the frame shows `NO POSE DETECTED` / `PLEASE FACE THE CAMERA` and the metrics are flagged with `pose_detected = False`.

### 4. Angle calculation

All exercise logic is built on one helper in `core/base_exercise.py`. Given three landmarks A, B and C, it computes the angle at B from the dot product of the vectors BA and BC:

```
angle = degrees( arccos( (BA · BC) / (|BA| × |BC|) ) )
```

The cosine is clamped to [-1, 1] and a zero-length vector returns 0°, so noisy landmarks can't crash the maths. Landmark coordinates are MediaPipe's normalised image coordinates (0 to 1), so every distance tolerance below is a fraction of the frame width or height.

### 5. Syncing metrics to the page

`services/tracking/metrics.py → sync_metrics_update()` runs in the Streamlit script. It reads the processor's latest metrics, copies them into `st.session_state`, and works out progress:

```
sets_completed   = total_reps // reps_per_set
current_set_reps = total_reps %  reps_per_set
```

While the stream is playing, the script reruns every 0.25 s so the sidebar stays current.

### 6. Saving history

Whenever `sets_completed` goes up, the newly finished sets, their reps and the time since the previous set are written with `add_exercise()`. Rows are merged per user, exercise and day, so each exercise has one running total per day.

### 7. Voice coaching

`services/coaching/voice_pipeline.py` decides when the coach speaks:

- **Milestones** (`workout_started`, `set_completed`, `workout_completed`) always produce a cue.
- **Form checks** (`ongoing_form_check`) and **missing pose** (`no_pose_detected`) produce a cue only when there is an actual issue, and at most once every **5 seconds**.

The metrics are first turned into a plain-English issue (see the table below). `LLMCoach` then sends the system prompt, the last 10 coach replies and a message such as `Event: ongoing_form_check Form Issue: The user's hips are sagging…` to `llama-3.3-70b-versatile` (temperature 0.4). The system prompt asks for 10 to 15 word, second-person, safety-first cues.

The reply is converted to MP3 with **gTTS**, auto-played through a hidden `st.audio` element, and also shown on the page as a **Coach:** message.

## Exercise Logic

Each detector in `detectors/` only counts a rep when the key joints for that exercise have visibility of at least 0.7.

| Exercise | Joint angle used for reps | Rep rule | Form checks |
|---|---|---|---|
| **Squats** | Knee: hip–knee–ankle, on the side with the more visible knee | Below **100°** = down; back to **160°** or more = 1 rep | Back angle (shoulder–hip–knee); depth status `GOOD DEPTH` / `TOO HIGH` / `STANDING` |
| **Push-ups** | Elbow: shoulder–elbow–wrist | Below **90°** = down; above **160°** = 1 rep | Body line (shoulder–hip–ankle): above 160° `Straight`, above 140° `Slight Bend`, else `Poor Form`. Hip height compared with the shoulder–ankle midpoint (tolerance 0.08): `LEVEL` / `SAGGING` / `PIKED UP` |
| **Biceps Curls** | Elbow: shoulder–elbow–wrist | Below **50°** = up; above **160°** = 1 rep | Elbow drift from the shoulder line (tolerance 0.06): `STABLE` / `ELBOW DRIFTING`. Torso tilt from vertical above 15°: `SWINGING` |
| **Shoulder Press** | Elbow: shoulder–elbow–wrist | Above **160°** = up; below **90°** = 1 rep | Extension: `FULL EXTENSION` (≥160°), `NEARLY EXTENDED` (≥130°), `PRESSING` (≥90°), `START POSITION`. Back (shoulder–hip–knee): `Neutral` (≥160°), `Slight Arch` (≥140°), `Excessive Arch` |
| **Lunges** | Front knee: the leg with the smaller knee angle | Below **100°** = down; above **160°** = 1 rep | Torso angle (shoulder–hip–knee). Shoulder midpoint vs hip midpoint, sideways (tolerance 0.10): `BALANCED` / `OFF BALANCE` |

Metrics that trigger a spoken correction:

| Exercise | Condition | Issue sent to the coach |
|---|---|---|
| Squats | Depth `TOO HIGH` | Squat not deep enough |
| Squats | Back angle below 130° | Leaning too far forward |
| Push-ups | Body `Poor Form` | Body not straight |
| Push-ups | Hips `SAGGING` / `PIKED UP` | Hips sagging / hips too high |
| Biceps Curls | `SWINGING` | Torso swinging during the curl |
| Biceps Curls | `ELBOW DRIFTING` | Elbow drifting away from the side |
| Shoulder Press | `Excessive Arch` / `Slight Arch` | Arching the lower back / brace the core |
| Lunges | `OFF BALANCE` | Losing balance |

## Getting Started

### Prerequisites

- Python 3.12 (tested with 3.12.4). MediaPipe 0.10.14 supports Python 3.9 to 3.12.
- A webcam and a browser that allows camera access.
- A Groq API key, free at [console.groq.com](https://console.groq.com).

### 1. Clone and install

```bash
git clone https://github.com/Amanjaiiinnn/AI_GYM_TRAINER.git
cd AI_GYM_TRAINER
python -m venv venv
```

Activate the environment:

```bash
# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

Install the dependencies:

```bash
pip install -r requirements.txt
```

### 2. Add your Groq API key

Create a file named `.env` in the project folder:

```env
GROQ_API_KEY=your_groq_api_key
```

The app reads `GROQ_API_KEY` from the environment first and then from Streamlit secrets (`.streamlit/secrets.toml`), so either works. The key is required: the coach calls Groq as soon as you start a workout. Keep `.env` and `secrets.toml` out of version control.

### 3. Run

```bash
streamlit run main.py
```

Run the command from the project folder. The app loads `static/` and `ml_models/` relative to the current directory. Streamlit opens the app at `http://localhost:8501`.

## Using the App

1. Enter a unique name and click **Start Session**.
2. In the sidebar, choose an exercise, the number of sets and the reps per set.
3. Click **Start Workout**. The coach greets you.
4. Click **START** on the video panel and allow camera access.
5. Step back until the joints for your exercise are in frame. The app follows whichever side of your body is most visible, so a side-on view works well for squats, push-ups and lunges.
6. Train. The sidebar shows your reps, set progress and live form metrics, and the coach speaks when you finish a set or when your form needs fixing.
7. Click **End Workout** when you're done. The **Workout History** table shows today's totals per exercise.

## Database

The SQLite file `data.db` is created automatically next to `main.py` the first time the app runs.

**`users`**

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER | Primary key, autoincrement |
| `username` | TEXT | Unique, not null |
| `created_at` | TIMESTAMP | Defaults to the current time |

**`exercises`**

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER | Primary key, autoincrement |
| `user_id` | INTEGER | References `users(id)` |
| `exercise_name` | TEXT | One of the five exercises |
| `sets` | INTEGER | Sets completed that day |
| `reps` | INTEGER | Reps completed that day |
| `time` | INTEGER | Seconds spent on those sets |
| `created_at` | TIMESTAMP | Defaults to the current time |

A new set for an exercise that already has a row today is added to that row instead of creating a new one. The history table groups today's rows by exercise and date.

## Customisation

| What | Where |
|---|---|
| Rep thresholds and form tolerances | Class constants at the top of each file in `detectors/` |
| Pose model confidence | `PoseLandmarkerOptions` in `services/vision/exercise_video.py` |

| LLM model and temperature | `services/coaching/llm.py` |
| Minimum gap between form cues (5 s) | `process_event()` in `services/coaching/voice_pipeline.py` |
| Wording of form issues | `_find_form_issue()` in `services/coaching/voice_pipeline.py` |
| Theme colours | `.streamlit/config.toml` |
| Adding an exercise | Subclass `BaseExercise`, register it in `VideoProcessorClass`, and add it to `EXERCISE_OPTIONS` and `METRICS_FIELDS` |

## Project Explanation

AI Real-Time Gym Coach is a computer vision-based fitness assistant that helps users track workouts through their webcam. The app uses MediaPipe to detect human body landmarks in real time and then analyzes joint angles to understand exercise movement, form, and repetitions.

The user first enters a username, selects an exercise, and sets a workout goal by choosing the number of sets and reps. Once the workout starts, the webcam stream is processed frame by frame. The app detects body landmarks such as shoulders, elbows, hips, knees, and ankles, then passes those landmarks to exercise-specific detector classes.

Each detector contains logic for one exercise. For example, the squat detector checks knee angle, back angle, and squat depth. The push-up detector checks elbow angle, body alignment, and hip position. Similar logic is implemented for biceps curls, shoulder press, and lunges.

The app keeps track of total reps, current set reps, completed sets, and exercise-specific form metrics. When a set or workout is completed, the data is saved locally using SQLite so the user can view workout history.

The project also includes an AI coaching layer. Groq is used to generate short coaching feedback based on workout events or detected form issues. The generated feedback is converted into speech using gTTS, allowing the app to provide voice-based workout guidance.

Overall, this project combines real-time computer vision, exercise biomechanics, AI feedback, voice coaching, and local data persistence into one interactive Streamlit application.
